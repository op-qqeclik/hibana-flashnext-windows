# reference/ — 原始记录（未润色）

这里的四份文件是**工作现场的原始记录**，不是给读者看的成品文档。保留它们的理由是：
`docs/` 里的每个结论都能在这里找到出处，包括**被推翻的中间结论**。

| 文件 | 内容 | 读法 |
|---|---|---|
| `HANDOFF.md` | 3 000+ 行 / 93 个小节，逐轮记录 45 轮优化（device 预算、内核勘察、否决项、每次实测） | 按 `## ` 小节跳读；注意它**写作过程中多次自我修订**，同一指标可能有多个版本（`docs/04` §9.5 列了最重要的 6 处） |
| `LESSONS.md` | 可复用教训（Windows 移植 / 性能测量 / 工程纪律三类） | 先读这一份，最省时间 |
| `kernel-fusion-spec.md` | 内核层勘察：哪些融合做不了、为什么、`quant_fp8_small` 并行化为什么净亏 | 想动内核之前必读 |
| `next-window.md` | 开机/交接清单 | 接手时照做 |

**已知的时间戳口径**：`HANDOFF.md` 里的部分数字早于 `docs/04` 的最终口径（例如 MoE 占 device 时间的
占比从 52% 下修到 46.6%，再被按 kernel 归属重算）。**以带仪器 + 带日期的那个为准。**

与公开环境的 IP 无关；仓库里没有任何凭据。
